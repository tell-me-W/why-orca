업무에 적용할 때는 에이전트의 수보다 작업의 경계를 먼저 정합니다. 무엇을 맡기고, 어떤 결과를 받으며, 누가 통합할지 정해 두면 완료 보고를 실제 판단으로 연결하기 쉽습니다.

작업 명세와 수정 범위

작업을 나눌 때는 각 작업이 다른 작업의 미완성 상태 없이도 진행될 수 있는지 확인합니다. 독립적인 작업은 병렬로 진행하고, 앞선 결과가 필요한 작업에는 의존 관계를 둡니다. Orca의 Task는 명세와 의존 관계, 상태를 관리하며, 조정자는 이 정보를 바탕으로 작업을 배정합니다. Orca 오케스트레이션

작업 요청에는 목적만 적기보다 아래 항목을 함께 전달하는 편이 좋습니다. 수정 범위가 겹친다면 담당자를 정하거나 실행 순서를 조정합니다.

완료 조건과 검토 책임

작업자의 완료 보고에는 무엇을 바꾸었고 어떻게 확인했는지 담겨야 합니다. 감독형 오케스트레이션에서는 현재 Task와 Dispatch에 연결된 worker_done으로 성공 또는 실패를 보고합니다. 이 메시지는 해당 실행 시도의 결과를 전달하며, 코드의 최종 채택 여부는 별도의 검토가 필요합니다. 작업자 보고 규칙

작업 조정의존 관계와 질문을 확인하고, 다음 작업에 필요한 결과를 전달합니다.
검토와 통합변경 내역과 요구사항을 비교하고, 결과를 합친 상태에서도 필요한 검증을 수행합니다.

한 사람이 여러 역할을 맡을 수 있지만, 마지막 검토와 통합을 누가 맡는지는 분명해야 합니다. 각 worktree에서 통과한 테스트만으로 통합 결과까지 확인했다고 볼 수는 없습니다.

처음에는 서로 독립적인 두 작업 정도로 시작해 조정 과정을 관찰해 볼 수 있습니다. 작업별 수정 범위와 완료 조건을 정하고, 결과를 받은 뒤 변경 내역과 검증 근거를 함께 확인합니다. 중간에 사람이 개입한 이유도 기록하면 다음 작업 명세를 개선할 수 있습니다.

평가할 때는 전체 소요 시간뿐 아니라 검토·재작업에 든 시간, 사용량, 결과 품질을 함께 봅니다. 병렬 처리가 유리했던 부분과 오히려 기다림이 늘어난 부분을 구분해야 다음에 어떤 일을 맡길지 판단할 수 있습니다.
