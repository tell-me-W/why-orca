이유 4 · 작업의 연속성

중단된 작업을 다시 이어가기

작업 환경 복원, 프로세스 재시작, 저장된 대화 재개의 차이를 알아봅니다.

11:00–12:00수정 2026-10-29
이 페이지의 목차
  • 작업 화면과 실행 중인 프로세스
  • 종료된 에이전트를 다시 실행하기
  • 저장된 대화를 찾고 이어가기

여러 작업을 오가다 보면 다시 시작할 때 어느 브랜치와 터미널에서 무엇을 했는지 찾는 데 시간이 듭니다. Orca는 작업 화면을 복원하고, 종료된 에이전트를 다시 실행하며, 저장된 세션을 찾아 재개하는 기능을 제공합니다. 화면 복원, 프로세스 재시작, 대화 재개를 나누어 이해하면 무엇을 이어갈 수 있는지 정확히 판단할 수 있습니다.

작업 화면과 실행 중인 프로세스

Orca를 다시 열면 열어둔 worktree, 탭과 분할 배치, 터미널 출력 기록, 선택했던 화면이 복원됩니다. 앱을 닫은 동안 백그라운드 데몬이 살아 있었다면 에이전트는 계속 실행되고, 다음 실행에서 같은 프로세스에 다시 연결합니다. 공식 문서: Session restore

컴퓨터 재부팅이나 데몬 장애로 프로세스가 종료됐다면 상황이 다릅니다. 작업 화면과 마지막으로 저장된 출력은 복원돼도 에이전트 프로세스는 다시 실행해야 합니다. 따라서 “Orca를 다시 켜면 언제나 모든 작업이 중단 없이 이어진다”라고 설명해서는 안 됩니다. 공식 문서: 복원되지 않는 것

종료된 에이전트를 다시 실행하기

Orca가 인식한 에이전트 프로세스가 종료되면 탭에 Restart 기능이 나타납니다. 이를 사용하면 같은 작업 디렉터리에서 해당 에이전트를 다시 실행할 수 있습니다. 작업 폴더와 실행 대상을 다시 찾는 단계를 줄여 주는 기능입니다. 공식 문서: Restart chip

같은 디렉터리에서 프로세스를 시작하는 것만으로 이전 대화의 모든 맥락이 복원된다고 볼 수는 없습니다. 대화를 계속하려면 저장된 세션이 있는지, 해당 에이전트가 그 세션을 재개할 수 있는지 따로 확인합니다. 사내 OpenCode가 종료된 상황도 이 두 단계를 구분해 설명합니다.

저장된 대화를 찾고 이어가기

Agent Session History는 지원되는 에이전트가 디스크에 남긴 세션을 읽습니다. 제목, 작업 디렉터리, 브랜치, 모델과 대화 미리보기로 기록을 찾고, 지원되는 세션의 Resume를 통해 재개 명령을 실행할 수 있습니다. OpenCode도 검색 대상이며, 공식 문서는 기존 세션 파일과 opencode.db를 읽는다고 안내합니다. 공식 문서: Agent session history

업무에서는 이전 요청과 답변을 다시 읽고, 현재 코드 상태를 확인한 뒤 후속 작업을 시작하는 데 활용합니다. 사내 변경판이 기록 경로나 형식을 바꿨다면 검색과 재개가 되는지 확인해야 합니다. 세션 검색, 전체 대화 안 검색, 재개 가능 여부도 각각의 지원 조건을 확인합니다. 복원 성공만으로 이전 맥락의 완전한 보존을 보장하지 않습니다.
