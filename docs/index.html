OpenCode + Orca

내가 Orca를 사용하는 이유

작업을 나누고, 상태를 살피고, 결과를 검토하고, 중단된 일을 이어가는 개발 흐름.

이 페이지의 목차
  • 이 강의에서 가져갈 것
  • 20분 발표 순서
  • 공식 기능과 실제 경험을 구분하기

이미 설정된 OpenCode로 코딩 작업을 맡기고 있다면, 다음 고민은 여러 작업을 어떻게 운영하느냐입니다. 어느 에이전트가 어떤 파일을 고치는지, 무엇을 기다리는지, 결과를 어디서 검토하는지 챙겨야 합니다.

이 강의는 병렬 실행 → 상태 확인 → 코드 리뷰 → 작업 재개 → 화면 검증이라는 다섯 가지 사용 이유를 중심으로 Orca를 설명합니다. Git worktree와 스킬을 이용한 오케스트레이션은 첫 번째 이유를 이해하는 데 필요한 개념으로 다룹니다.

이 강의에서 가져갈 것

  • OpenCode, Orca의 역할을 구분합니다.
  • Worktree로 나뉘는 것과 오케스트레이션으로 관리하는 것을 설명할 수 있습니다.
  • 실행 상태를 보고 개입하고, Diff와 화면으로 결과를 확인하는 흐름을 이해합니다.
  • 공식 지원 기능과 사내 환경에서 확인할 조건을 구분합니다.

20분 발표 순서

  1. 1다섯 가지 사용 이유OpenCode · Orca의 활용1분
  2. 2Git worktree 이해작업 파일은 따로, 저장소 이력은 함께3분
  3. 3스킬과 오케스트레이션작업 배정 · 의존 관계 · 완료 보고3분
  4. 4터미널과 상태 추적내가 응답해야 할 작업 찾기2분
  5. 5Diff 검토와 피드백줄별 의견을 모아 재수정 요청2분
  6. 6세션 복구와 이력복원 · 재시작 · 대화 재개 구분1분
  7. 7브라우저와 Design Mode요소 선택부터 수정 결과 확인까지2분
  8. 8발표자의 실사용 사례직접 작성할 사례와 화면 자료4분
  9. 9정리와 팩트체크요점 정리와 Q&A2분

설명 14분, 실사용 사례 4분, 정리와 질문 2분입니다. 세부 명령과 운영 방법은 접힌 보충 설명 및 업무 적용 부록으로 분리했습니다.

공식 기능과 실제 경험을 구분하기

제품 기능은 2026년 10월 29일에 Orca·OpenCode·Git 공식 문서로 확인했습니다. 각 장에는 근거 링크가 있고, 마지막 장에는 원문 주장별 팩트체크를 모았습니다.

OpenCode는 사내 LLM API에 이미 연결된 상태를 전제로 합니다. 이 강의는 OpenCode와 Orca를 함께 사용하는 작업 흐름에 집중합니다. 실제 환경에서의 상태 감지와 대화 재개, 실사용 사례와 성과는 직접 확인해 채웁니다.
