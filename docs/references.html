정리와 팩트체크

다섯 가지 이유의 확인 결과와 조건을 정리하고 공식 자료로 연결합니다.

다섯 가지 사용 이유는 공식 기능과 대체로 일치합니다. 다만 사내 OpenCode의 무응답 대응은 사용 효과로 확인해야 하고, 세션 복구는 복원·재시작·대화 재개로 구분해야 합니다. 아래는 2026년 10월 29일 기준 확인 결과입니다.

발표를 마치며

Orca를 쓰는 이유는 에이전트를 여러 개 실행하는 데서 끝나지 않습니다. 작업을 나누고, 개입할 곳을 찾고, 변경을 검토하고, 이전 일을 이어가며, 화면에서 결과를 확인하는 흐름을 만들기 위해서입니다. 이 흐름이 실제 업무에서 얼마나 도움이 됐는지는 앞의 실사용 사례로 설명합니다.

  • Worktree는 수정할 공간을, 오케스트레이션은 할 일과 관계를 나눕니다.
  • 상태와 알림으로 확인할 대상을 찾고, Diff와 테스트로 결과를 판단합니다.
  • 복구와 브라우저 연동은 사용 중인 에이전트와 환경의 지원 범위를 확인합니다.

원문 주장별 팩트체크

확인은 공식 문서에 기능이 명시됐다는 뜻입니다. 조건부는 버전·설정·연동 조건이 있으며, 효과 검증 필요는 실제 업무 기록으로 입증할 부분입니다.

공식 제품 기능과 사내 환경에서 확인할 부분
원문 주장판정강의에 반영한 설명과 근거
Git worktree 기반 작업 분리확인작업 폴더를 분리합니다. 권한 격리나 무충돌 병합을 뜻하지 않습니다. Orca worktrees, Git
여러 OpenCode 동시 실행확인OpenCode 지원과 여러 에이전트 실행이 명시돼 있습니다. 사내 설정은 별도 확인합니다. Supported agents
작업 분배·의존성·진행 관리조건부오케스트레이션은 실험 기능입니다. 실행 중 runtime과 스킬·설정이 필요합니다. Orchestration
실행 상태를 한눈에 확인확인터미널 탭의 상태와 Agents feed를 활용합니다. Terminal, Agents feed
완료·대기 알림조건부알림 및 응답 대기 표시를 지원하며, 세션 종류와 설정에 따라 전달 방식이 다릅니다. Notifications
OpenCode 먹통에 빠른 대응효과 검증 필요상태·출력을 확인하는 데 도움이 됩니다. 임의의 무응답 원인 판정이나 자동 복구를 보장하지 않습니다. 상태 감지 방식
AI 코드 Diff 비교확인Worktree 변경과 선택한 기준을 비교합니다. Diff viewer
코드에 Annotate 의견 작성확인Diff의 줄이나 범위에 의견을 연결합니다. Annotate AI Diff
여러 의견 일괄 재수정 요청확인의견을 하나의 프롬프트로 묶어 전송합니다. 수정 성공은 다시 확인합니다. Send to agent
Orca 재실행 시 환경 복원조건부화면·출력 기록을 복원합니다. 같은 프로세스 재연결은 데몬이 살아 있을 때 가능합니다. Session restore
OpenCode 종료 후 재시작조건부인식된 에이전트를 같은 디렉터리에서 다시 실행합니다. 대화 재개와는 구분합니다. Restart
과거 대화·작업 기록 검색확인OpenCode 저장 기록도 지원 대상입니다. 사내 변경판의 저장 형식은 확인해야 합니다. Session History
이전 맥락을 유지해 이어가기조건부저장된 세션과 에이전트의 Resume 지원에 달려 있습니다. Resume
내장 브라우저로 화면 확인확인Worktree별 브라우저로 개발 서버를 엽니다. 서버 실행은 별도로 필요합니다. Per-worktree browser
Design Mode로 UI 수정·검증조건부선택한 요소의 맥락을 에이전트에 전달해 소스 수정을 요청하고 결과를 확인합니다. Design Mode

사내 환경에서 확인할 항목

아래는 공식 지원과 별도로 실제 사용 예시를 준비할 때 확인할 항목입니다. 아직 결과를 측정하거나 확인한 것으로 읽지 않습니다.

  • Orca에서도 기존 OpenCode 실행 환경이 유지되는가?
  • 작업 중, 입력 대기, 완료, 프로세스 종료가 실제 상태와 맞게 표시되는가?
  • Annotate 의견이 의도한 에이전트에 전달되는가?
  • 기존 세션이 검색되고 재개되는가? 앱 종료와 프로세스 종료 후의 동작은 각각 어떤가?
  • Design Mode 요청의 요소 정보와 이미지가 사용 중인 에이전트·모델에서 처리되는가?

공개 발표에는 실제 API 주소나 키를 넣을 필요가 없습니다. 설정 항목과 확인 결과만 설명하면 됩니다.

버전이 다른 문서를 읽을 때

공식 웹 문서와 공개 저장소의 문서도 시점에 따라 다를 수 있습니다. 이번 조사에서는 OpenCode worker의 모델·effort 옵션 설명에 차이를 확인했으므로 해당 실행 옵션을 고정 예제로 넣지 않았습니다. 실제 실행은 설치된 Orca의 가이드를 기준으로 합니다. 웹 문서, 저장소 문서

orca status --json
orca skills get orca-cli
orca skills get orchestration --full

위 명령은 상태와 사용 지침을 조회합니다. 운영체제·설치 방식에 따른 CLI 이름은 공식 CLI 안내에서 확인합니다.
