이유 1 · 배정과 진행 관리

스킬로 여러 에이전트의 일 연결하기

독립 작업은 병렬로 맡기고, 의존하는 작업은 결과를 확인한 뒤 이어갑니다.

이 페이지의 목차
  • 사람, 조정자, 작업자의 역할
  • Orca 스킬은 도구를 쓰는 절차다
  • 같이 시작할 일과 기다릴 일을 구분한다
  • OpenCode에서 시작하기 전 확인할 것

여러 OpenCode를 켜 두면 작업을 동시에 진행할 수 있습니다. 그다음에는 누가 무엇을 맡고, 어떤 결과를 기다리며, 언제 끝났는지를 관리해야 합니다. Worktree는 수정할 공간을 나누고, 오케스트레이션은 그 안에서 수행할 일을 연결합니다.

사람, 조정자, 작업자의 역할

사람이 목표와 검토 기준을 정하면, 조정자(coordinator) 역할의 에이전트가 작업을 나눠 맡깁니다. 작업자(worker)는 배정받은 일을 수행하고 결과나 질문을 돌려줍니다. Orca는 이 과정의 작업, 배정, 메시지와 완료 상태를 관리합니다. 공식 오케스트레이션 문서

Orca 스킬은 도구를 쓰는 절차다

스킬은 에이전트가 Orca를 언제, 어떻게 사용할지 읽는 지침입니다. orca-cli는 worktree·터미널·내장 브라우저를 다루고, orchestration은 작업자를 감독하며 질문과 완료 보고를 주고받는 절차를 안내합니다. 에이전트가 스킬을 읽고 CLI를 호출하면 실행 중인 Orca가 요청을 처리합니다. 공식 스킬 안내

따라서 “스킬을 설치했다”와 “협업 작업을 실제로 배정했다”는 서로 다른 단계입니다. 에이전트가 할 일과 수정 범위, 완료 조건을 이해해야 협업도 시작할 수 있습니다.

같이 시작할 일과 기다릴 일을 구분한다

  1. 범위를 나눈다. 작업마다 담당 파일과 원하는 결과, 확인할 테스트를 정합니다.
  2. 독립적인 일을 함께 시작한다. 서로의 결과가 없어도 진행할 수 있는 작업을 병렬로 맡깁니다.
  3. 결과를 확인한 뒤 다음 일을 맡긴다. 선행 결과가 필요한 작업에는 의존 관계를 둡니다.

작업 간 선후 관계를 순환 없이 연결한 구조를 DAG라고 합니다. Orca는 작업의 의존성과 상태를 기록하지만, 작업을 잘 나누고 결과를 검토하는 책임까지 대신하지는 않습니다. 같은 worktree에 여러 작업자를 배정할 수도 있으므로 파일을 분리하려면 작업자별 worktree를 실제로 선택해야 합니다. Task 의존성과 worker 배정

보충 · Run, Task, Dispatch는 무엇인가요?
Run
한 협업의 작업과 조정자 수신함을 묶습니다. Run 자체가 작업자를 자동 배치하는 스케줄러는 아닙니다.
Task
할 일과 의존성, 진행 상태를 기록합니다.
Dispatch
한 작업을 작업자에게 맡긴 수행 시도입니다. 재시도할 때 이전 보고와 구분합니다.
완료 보고
worker_done에 결과를 담습니다. 작업 중이라는 heartbeat와 구분하며, 보고가 왔다고 테스트나 병합까지 완료된 것은 아닙니다.

작업자는 ask로 조정자에게 질문합니다. 조정자는 decision gate로 특정 작업을 결정이 내려질 때까지 보류할 수도 있습니다. 공식 개념과 메시지 설명

OpenCode에서 시작하기 전 확인할 것

OpenCode는 Orca의 지원 에이전트입니다. 다만 오케스트레이션은 실험 기능이며 Settings → Experimental에서 활성화하고 Orca runtime을 실행해야 합니다. 사내 OpenCode의 명령·플러그인 구성과 설치 버전에서 작업자 실행 및 완료 보고까지 확인한 뒤 사용합니다. 지원 에이전트 · 실행 전제

orca status --json
orca skills get orca-cli
orca skills get orchestration --full

위 명령은 상태와 설치 버전의 가이드를 조회합니다. 실제 명령 이름은 실행 환경에 따라 다를 수 있습니다. 모델 선택 같은 세부 옵션은 이 가이드를 따르고, 폐기된 orca orchestration run 예제는 사용하지 않습니다. 버전에 맞는 가이드 불러오기
